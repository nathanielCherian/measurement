Packet trains (WebTransport or WebRTC DataChannel)

A train is N packets handed to the transport back to back, repeated every gap. The receiver measures the spacing they arrive with. Each packet is stamped as the sender hands it over, so send-side spread shows how much the browser's own pacer (or SCTP) spread the burst before the wire; dispersion at the receiver reflects the bottleneck. The HTTP POST transport sends each packet as a POST over TCP (up only): loss is repaired below you and the browser may spread the burst over several sockets, so it measures something different — the report says how many connections the server saw. Implied rate = (N−1) × size × 8 / dispersion. Other pages: WebTransport probe, WebRTC probe.
